# 设计初始化检查

在仓库根目录使用已安装的npm工作区依赖运行：

```powershell
npm ci
npm run check:architecture
```

本检查只读取设计SQL、vnext类型与公开配置，在 `:memory:` 建立SQLite并关闭；不读写真实用户库、不触发旧迁移、不读取凭据、不访问模型、不启动应用。

DDL检查使用Node自带的 `node:sqlite`（Node 22.13及以上），不加载当前业务的原生SQLite插件。当前机器为Node 24.19.0；现有better-sqlite3在测试进程退出时发生原生清理断言，须在下一阶段工具链修复中单独核对，设计SQL检查通过不能代表其运行兼容性已解决。

验证范围：DDL与关键表、外键、唯一来源/排序、原位置相同文本保留、树单父/跨会话拒绝、AI/OCR来源提示约束、相对路径、FTS同步、附件跨文档来源授权、标注历史绑定保留及歧义来源拒绝、公开配置不含凭据、前端接口无通用文件/Key调用、新三栏状态无浮卡字段；纯类型检查还区分无会话术语来源和强制授权的会话证据。撤销授权后的新请求拒绝、重定位匹配质量及人工确认仍需后续运行时检查。

这些是架构资产检查，不能证明完整业务、真实多格式解析、大文件性能、安全运行时校验、迁移无损或三栏视觉已经实现。现有业务的 `npm run typecheck` 与生产构建属于独立基线；不能以此检查通过替代业务验收。
