# DeckLens Electron 壳：后续接入边界

状态：架构设计占位。本目录当前只提供职责说明，不包含 Electron 业务、依赖、package 文件、启动代码、安装器或打包逻辑；本轮不是桌面功能交付。

## 同一仓库与同一核心

桌面版后续复用纯 Node core 和 `apps/web` 的 Vue 3 + Vite 构建产物。解析、文档模型、术语、探索树、检索、AI、SQLite 与迁移全部留在 core；壳负责 Electron 生命周期、平台能力与受控传输。

浏览器版通过 HTTP adapter 访问仅监听 127.0.0.1 的本地服务。桌面版通过 IPC adapter 调用主进程持有的 core，不再启动独立 HTTP 服务。前端组件只依赖统一 PlatformAdapter，不能在业务组件散落 isDesktop 判断。

```text
同一 web 构建产物
  └─ PlatformAdapter
     ├─ 浏览器：HTTP adapter → 本地 Node 服务 → core
     └─ 桌面：IPC adapter → preload 白名单桥 → 主进程 → core
```

纯 Node core 不 import Electron、Vue 或浏览器对象。平台文件选择、用户目录定位等能力通过宿主依赖注入，业务结果保持一致。未来桌面版运行时随安装包携带，不要求普通电脑预先安装 Node 或 VS Code；该独立运行能力须在后续真实打包阶段验收。

## 主进程、preload 与 renderer

| 层 | 职责 | 允许暴露的数据 |
| --- | --- | --- |
| 主进程 | 创建窗口、定位用户目录、持有 core、协调数据库与后台任务、文件选择、系统生命周期 | 经校验和脱敏的业务 DTO、受控文件/资源 ID、任务状态 |
| preload | 通过 contextBridge 暴露逐个命名的白名单方法，转发已定义参数与结果 | PlatformAdapter 必需能力；不暴露通用 ipcRenderer 或任意 channel 调用 |
| renderer | 运行同一前端产物，展示固定三栏、术语、标注和探索 composer | 文档内容、来源、节点、设置公开字段、keyConfigured 状态 |

BrowserWindow 明确设置 `contextIsolation: true`、`nodeIntegration: false`；按后续 Electron 兼容验证启用 renderer sandbox，并以隔离方案为基线。渲染进程不接触 Node 文件系统、真实密钥、本机任意文件或主进程实例。

主进程逐条注册 IPC handler，校验 sender/frame 是否属于应用自有窗口，再用共享 schema 校验参数、返回值和资源归属。拒绝任意文件路径、任意方法名、任意命令执行、可构造的通用 IPC 与跨文档资源越权。preload 的 TypeScript 类型不能代替主进程运行时校验。

窗口只加载应用自有构建产物；新窗口、导航和外部协议走明确策略。文档中的 HTML、Markdown、SVG 与超链接均按不可信内容处理。不能为了预览远程内容关闭 webSecurity，也不能授予文档页面 Node 能力。

## 统一 adapter 的桌面映射

后续 IPC adapter 需要覆盖现有前端能力：文档导入/重解析/删除、章节树与内容块、资源读取、章节调整、术语、探索节点与边、问答、会话与视图状态、公开模型设置、本机密钥配置入口及清理操作。每个方法独立白名单映射，返回统一错误码与具体原因。

- 文件选择返回宿主管理的句柄/导入任务 ID；renderer 不指定任意绝对路径。
- 图片和附件通过受控资源 ID 访问，主进程验证对应记录与相对路径，并确认解析后的路径仍位于 DeckLens 用户目录内。
- 自定义资源协议如后续采用，只映射已登记资源，正确设置 MIME/CSP；不能成为任意文件读取代理。
- 标注和 composer 只传语义锚点、附件 ID 与标注 ID；添加上下文不自动提交问答。
- AI Provider 调用在主进程持有的 core 中完成。renderer 仅获得是否配置密钥、公开 base URL、模型名与能力声明。
- 密钥配置编辑入口只打开固定的本机配置文件，不能接受 renderer 指定路径；API Key 不经 IPC 返回，不进 SQLite、日志、仓库或前端构建。

浏览器 HTTP 与 Electron IPC 共用相同 core 业务和参数 schema。同一文件在两种通道下的统一模型、sourceOrder、章节树、图片归属、术语和引用必须一致。

## 后续启动与数据规则

建议启动顺序：取得单实例锁 → 定位系统用户数据目录 → 初始化文件目录及 core → 执行 SQLite 迁移 → 注册 IPC/资源白名单 → 创建安全窗口 → 加载 web 产物 → 恢复文档与探索状态。关闭窗口时按宿主策略结束任务并释放数据库；大文件解析不能阻塞界面线程。

用户目录由主进程使用操作系统用户数据位置定位并注入 core。数据库、原始文件、图片、附件、标注、笔记、导出与真实配置均在该目录下，遵从 core 统一存储规则。浏览器版与桌面版的数据兼容不代表两进程可同时随意写同一目录；未来通过实例/目录锁明确并发使用策略。

数据库迁移沿用 core 迁移系统，不新建一套桌面 schema。升级前后的文档、手动章节、来源版本与探索路径必须保留。资源相对路径不依赖安装目录，安装包升级或移动不应改写用户来源路径。

## 本轮与后续验收

本轮仅新增本文档，不安装 Electron、不增加依赖或打包配置，不声明 exe 可运行。现有 web 浮卡草稿待下一阶段与固定三栏设计一起整合，不作为桌面专属 UI 继续开发。

桌面开发启动前先确认固定三栏与统一 adapter/contracts；之后单独验收白名单 IPC、密钥隔离、路径限制、迁移、关闭恢复以及无 Node 电脑的独立运行。账号、云同步、社交、付费、多人协作不在本版范围。
