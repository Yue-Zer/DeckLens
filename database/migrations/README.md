# 数据库迁移约定

当前目录只定义迁移流程，不包含可被应用执行的迁移。`../design/schema-vnext.sql` 是空库设计草案，**不是迁移文件**；不得由启动脚本、glob、core import 或迁移 registry 自动发现执行。现有 core 的旧迁移保持原样。

## 实施前准备

1. 架构和字段映射确认后，为每个已发布 schema 生成脱敏或合成 fixture，包含人工目录调整、重复文本、图片、历史探索、引用、注释和旧模型配置。
2. 建立映射清单：旧字段、新字段、默认值、不可恢复字段、保留旧 ID 策略与人工复核项。不从缺失信息伪造原文页码、节点父子关系或模型身份。
3. 为旧 source key 建立 alias；来源位置冲突标记待复核，不依靠全文文本相同自动合并两处来源。
4. 每个正式迁移使用递增整数版本、可读名称、不可变 SHA-256 checksum 和 UTC 应用时间登记 `schema_migrations`。已发布迁移不原地修改。

## 启动和事务顺序

- 存储驱动解析用户数据目录并取得应用写锁；所有连接先设置 `foreign_keys=ON`，再开始事务。不得在事务内切换此 pragma。
- 读取 migrations ledger，校验全部已应用 checksum；遇到比应用更新的 schema 停止写入并给出明确提示，不能降级覆写。
- 正式迁移前通过 SQLite backup API 或 `VACUUM INTO` 生成一致性备份。不能在运行中的 WAL 模式下只复制主 `.sqlite` 文件。
- 在独立迁移事务中建新表/复制/核对/替换，并登记版本；失败整体回滚，不将半迁移数据库标记为新版本。长时间数据派生任务另用可恢复 job，不让读取永远阻塞。
- 提交前执行 foreign_key_check、完整性检查及业务约束检查；包括 tree 无环、root/单父规则、引文版本归属、人工结构和注释数量保留。FTS 重建后执行其 integrity-check。
- 成功后才允许切换运行 schema；保留备份与迁移诊断，错误日志禁止含密钥、原文正文或原始供应商响应。

## 跨文件操作

密钥文件和媒体文件不能与 SQLite 共享事务。使用可恢复、幂等的 journal：准备数据库记录 → 写入临时文件并校验 → 原子替换 → 提交完成标记。重启能够继续或回滚；未确认完成前不删除旧文件。

旧单密钥配置迁移时创建固定 legacy provider profile，SecretStore 为它生成 opaque secret_ref，将密钥原子迁移到 `credentials/<providerId>.json`。SQLite 只存 ref，不存凭据。重复启动不能创建重复 profile；失败保留旧文件。公开 GET 只返回 `keyConfigured` / `configured` 等公开状态，设置页通过后端打开固定本机编辑器配置，密钥不经过浏览器或 renderer 的输入、请求或状态。

## 保留策略

- 解析版本是不可变证据；重新解析添加版本和绑定，不清空 chats、explore nodes、source refs、annotations、手动 section edits。
- 旧注释 target 与绑定保留，不能将历史引文原地重定向到新块。无法匹配的注释标记 orphaned，正文和原位置仍保留；一个旧目标拆入多个新块时通过 segment_index 保留各分段。
- 注释歧义使用 ambiguous；内容或版面指纹变化时使用 layout_stale 并保留旧 geometry。归一化坐标不视为跨版面精确映射。
- 问题附件不改变 chat 主文档；旧节点保留来源授权快照。撤销授权禁止新请求，保留旧 grant 行及历史证据，不把跨文档来源静默搬到主文档。
- 默认不自动回收被引用的旧版本。用户明确删除整份文档时，在同一事务内处理文档、探索、注释和派生数据，并在事务提交后安全删除未使用文件。
- 清空模型密钥与清空本地文档数据是独立操作。备份不默认包含 secret 文件；恢复凭据需要用户明确选择本机操作。

## 正式迁移验收

| 场景 | 必须满足 |
|---|---|
| 空库启动 | 自动建库并登记正式版本，基础浏览不依赖模型配置。 |
| 历史版本升级 | 文档/块/媒体数量、手工目录、探索路径、注释正文和来源保持可解释。 |
| 中断与磁盘失败 | 旧库可恢复，失败迁移无完成记录，重启幂等。 |
| 未知新 schema | 明确阻止旧应用写入，不丢数据。 |
| secret 文件升级 | 密钥不入 SQLite/日志/公开 API；多 profile 无串用。 |
| 外键与树 | foreign_key_check 空结果；跨 chat、跨版本、双 tree 父、自环被拒绝；服务检测一般环。 |
| 草稿与附件 | draft 节点归属同 chat；ready 附件必须有版本和 grant；未授权跨文档引用被 FK 拒绝，合法授权来源可引用。 |
| FTS | 插入、更新、删除同步，重建结果一致，检索文本与原文证据分离。 |
| 回归基线 | 在临时目录/内存和合成 fixture 测试，绝不对真实用户目录执行验证。 |

本目录目前只有此说明；迁移执行器、数据回填和实际 schema 版本升级均待后续确认后开发。
